# 玩家数值系统

## 数据分层

- `PlayerMainStats.asset`：策划基础值，作为每局计算的不变基线。
- `PlayerStatModifierCollection`：服务器上的局内修正器集合，管理叠层、时限、来源和聚合。
- `PlayerNetworkState`：每名玩家的局内状态，服务器聚合后只同步最终数值给客户端。
- `PlayerStatModifier`：升级卡、道具、Buff、装备和诅咒的统一接入参数。
- `BloodPacts.asset`：策划表中 37 条血契的 ScriptableObject 数据库。

基础配置位于 `Assets/Resources/GameBalance/PlayerMainStats.asset`。策划修改该资产即可改变下一局的初始值，运行时不要修改 ScriptableObject。

## 聚合规则

```text
最终值 = (基础值 + 固定值总和) × (1 + 叠加百分比总和) × 独立倍率乘积
```

- `Flat`：固定值，例如攻击 `+3`。
- `AdditivePercent`：同区间加算，`0.1` 表示 `+10%`。
- `Multiplicative`：独立乘算，`0.9` 表示变为原来的 `90%`。

聚合按修正器 ID 稳定排序，最终再按属性边界钳制。暴击率范围为 `0~1`；攻击间隔和闪现速度不会低于 `0.01`；最大生命四舍五入为整数。

## 添加局内修正器

修正器的增删必须在服务器执行：

```csharp
PlayerNetworkState player = ...;

// 永久攻击 +3，同 ID 再次添加会叠层，最多 5 层。
player.AddStatModifier(new PlayerStatModifier(
    modifierId: "upgrade.blood_blade",
    sourceId: "upgrade.blood_blade",
    stat: PlayerStatType.BaseAttack,
    operation: PlayerModifierOperation.Flat,
    value: 3f,
    maxStacks: 5));

// 持续 8 秒的移速 +20%；重复添加会刷新持续时间。
player.AddStatModifier(new PlayerStatModifier(
    modifierId: "buff.blood_rush.move_speed",
    sourceId: "buff.blood_rush",
    stat: PlayerStatType.MoveSpeed,
    operation: PlayerModifierOperation.AdditivePercent,
    value: 0.2f,
    durationSeconds: 8f));

// 攻击间隔乘 0.9，即攻速提升。
player.AddStatModifier(new PlayerStatModifier(
    modifierId: "upgrade.swift_attack",
    sourceId: "upgrade.swift_attack",
    stat: PlayerStatType.AttackInterval,
    operation: PlayerModifierOperation.Multiplicative,
    value: 0.9f));
```

`modifierId` 是叠层和精确移除的唯一键。同 ID 必须保持属性、阶段、数值、来源和持续时间一致，否则会拒绝添加，避免数值被静默覆盖。`durationSeconds <= 0` 表示本局永久。

## 移除和查询

```csharp
// 移除某个修正器的所有叠层。
player.RemoveStatModifier("upgrade.blood_blade");

// 一次移除某个 Buff/装备提供的多项修正。
player.RemoveStatModifiersFromSource("buff.blood_rush");

// 服务器或单机可获取计算明细，用于 Debug 或属性面板。
if (player.TryGetStatBreakdown(PlayerStatType.BaseAttack, out var detail))
    Debug.Log($"{detail.BaseValue} + {detail.FlatBonus} = {detail.FinalValue}");
```

`ResetForNewRun()` 会清空全部修正器，生命和体力回满，猩红值归零。为了兼容现有 Boss 奖励，`ApplyRunUpgrade(PlayerStatUpgrade)` 仍然保留，但新系统应优先使用 `PlayerStatModifier`。

## 血契数值接入

```csharp
BloodPactConfig database = BloodPactConfig.LoadDefault();

// 服务器上选择一条血契。正等级修改指定玩家，负等级修改全局敌人数值。
database.TryApplyNumericEffects("update_001", playerState);

// 新一局除了重置每名玩家，还需清空敌人侧血契修正。
BloodPactConfig.ResetEnemyNumericEffects();
```

- 普通数值列已接入：速度、攻击、生命、体力、暴击、冷却缩减、攻击范围、击退和无敌时长。
- `cooldownReduction` 为正数时会从攻击间隔中减去，例如 `0.1` 使 `1.0s` 变为 `0.9s`。
- `specialEffect` 只保留策划文本，当前不会注册流血、灼烧、领域、必定暴击等特殊逻辑。同一血契中已填写的普通数值仍会生效。

## 新版策划配置映射

- 玩家冲刺速度倍率和持续时间已转入 `PlayerMainStats.asset`，不再由 Player Prefab 硬编码。
- 玩家击退持续和眩晕时长已按新表更新为 `0.2s`。
- `EnemyDefaultStats.asset`、`EnemyRangedStats.asset`、`EnemyEliteStats.asset` 分别对应近战小怪、远程小怪和精英怪。
- 敌人的生命、伤害、移速、范围、攻击冷却和击退已支持全局局内修正。掉落数量/概率从各自的敌人配置读取。

## 其他规则

- 最大生命或最大体力增加时，会同时补充增加的上限差值；上限降低时会钳制当前值。
- 暴击由服务器每次挥砍只判定一次，同一挥砍命中的全部目标共享该次暴击结果。
- 弹反、强化子弹、远程徘徊范围等字段已进入敌人配置，但仍需对应战斗 AI/弹反系统消费后才会产生行为。

## 怪物奖励结算

- 怪物不再生成猩红资源、魔币或血包掉落物。
- 最后造成伤害的玩家获得该怪物的全部奖励；无法获取伤害来源时，奖励给怪物附近最近的存活玩家。
- `redResourceDropAmount` 直接增加玩家猩红值，`coinDropAmount` 直接增加 `CurrentCoins`。
- `healthPackDropChance` 判定成功时不再生成血包，而是直接将获奖玩家生命回满。
- 魔币为服务器权威局内数据，可通过 `CoinsChanged`、`AddCoins()` 和 `TrySpendCoins()` 接入 UI 与商店。新一局会归零。
